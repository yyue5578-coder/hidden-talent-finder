# 生成后检查

用户出歌后，别问"好听吗"。带用户只听三处，每处两三秒。

## 听三处

1. **人名、关键字有没有读对？** 中文多音字最容易错。比如"娜"可能被读成 nuó。校验脚本（`scripts/check_lyrics.py`）末尾的「读音风险」清单里列了歌词里的多音字（如咽、攥、转、折、传、长），重点听这几句。
2. **副歌第一句有没有被吞字？** 副歌第一句最容易因为太长被"赶"。
3. **结尾是自己收住的，还是被硬切的？**

## 每一处出问题怎么办

| 问题 | 处理 |
|---|---|
| 某个字读错 | 只重做那一小段，前面别动。反复读错就换一个同韵的字，如"攥"换成"握"，句尾不动就不影响押韵 |
| 副歌第一句被吞 | 把那句缩短，或在词后多留一个空格，重做那段 |
| 结尾被硬切 | 补两小节尾奏 |
| 整体氛围不对（太吵、太满） | 回到 `suno.md` / `haimian.md`，换一档或改几个词 |
| 念白被唱成了旋律 | 检查括号里有没有 `no melody`；还是不行，就把这一段删掉 |

**Suno：** 用 Replace Section 换一段，用 Extend 接尾奏。
**海绵音乐：** 用"改编"，只改出问题的部分。

## 原则

- **不要整首重跑。** 先定位到哪一段，只重做那一段。
- 一次让它生成两版，对比着听，比反复重跑更快。
- 重做之前，先确认歌词没问题。歌词有问题，改的是 `歌词定稿.md`，不是提示词。

## 最后的确认

问用户一句：

> 听完这首歌，是不是你想表达的那个感觉？

- 是 → 进入交付。
- 不是 → 问："是歌词不对，还是唱出来的感觉不对？" 歌词不对回到打磨；感觉不对回到提示词。
