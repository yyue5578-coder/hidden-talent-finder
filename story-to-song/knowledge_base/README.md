- 部分发行日期、编曲、作词人在不同来源之间有冲突，文件里已逐条标注，没有强行统一。
- 百度百科被验证拦截，没读到；部分背景只有单一来源或只见搜索摘要，文件的"来源"里已标明。

## 建库规则

- 只存分析，不存全词；每首最多引用 1–3 句关键句。
- 每首歌必须写明来源，作者、歌手、日期来自搜到的页面，不凭记忆填。
- 韵脚用 `scripts/check_lyrics.py` 计算，不目测；脚本对轻声和多音字会提示人工核对。
- 新增单曲后，回头更新对应场景的 profile，版本号加一，并更新本文件。

## 待补样本

1. 暗恋 / 心动：真正写"还没说出口"的歌，至少 3 首。
2. 生日 / 祝福：真正写生日、偏喜庆的歌，至少 3 首。
3. 怀念 / 释怀：再补 2–3 首"有释怀"的歌，让"怀念"和"释怀"两类样本更均衡。
4. 纪念 / 求婚：回望式纪念歌（回头看共同走过的年头、或写具体的纪念日）至少 2 首；"陪你把X变成了Y"式的长久陪伴写法；再补 1–2 首"当面问对方"的求婚歌。
5. 道歉 / 感谢：有具体补偿动作的道歉歌；对朋友、旧搭档的道歉；落在一件小事上的感谢朋友的歌；对在世母亲当面感谢的歌。
6. 亲情：母亲写给孩子的歌；手足歌（候选《给我的弟弟》《写给妹妹的歌》）；已故亲人的对照样本；爷爷 / 外公；儿子当面感谢父亲；"亲人做过的完整一件事"的正面样本。
