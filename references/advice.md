# 往哪走：位置、职业、城市

报告最后一块“往哪走”只有三样：一句话的位置、3 到 5 个职业名称、脚本给的城市。**都不解说**，依据放进 `evidence` 的“职业”一组（可选）。

## 一、位置（position）

一句话，说 TA 在一件事、一个团队里该站在哪：
- 一件事的开头 / 把复杂的东西讲给更多人听 / 最后把东西磨到能交付 / 两拨人中间 / 幕后把规则看透

从画像来：发动机决定“做什么”，风格方向决定“什么阶段、和谁一起”。

## 二、职业（careers）

- 3 到 5 个，只写名称，可以带一个很短的括号限定，例如“产品经理（新产品从 0 到 1）”。
- 主轴放在**发动机**上，“只是本事”的那几项当配角；`drain` 里的事不能是职业的主要内容。
- 优先选“两项本事合在一起才成立”的职业：

| 组合 | 可以考虑 |
|---|---|
| 讲清 + 看懂门道 | 知识类内容创作者、行业分析师、科普编辑 |
| 讲清 + 带人 | 培训师 / 课程设计师、发布会或活动主讲 |
| 拍板 + 开拓 | 产品经理（0 到 1）、创业项目发起人 |
| 点子 + 打磨 | 设计师、产品打磨、手作品牌主理人 |
| 拍板 + 看懂门道 | 选品、投资研究、咨询顾问 |
| 理顺 + 带人 | 项目经理、运营负责人 |
| 理顺 + 打磨 | 品控、交付、编辑 |
| 读懂人 + 看懂门道 | 用户研究员、客户成功 |

- 风格方向用来挑位置：开拓 → 新项目、第一版；深耕 → 长期打磨；快反馈 → 能很快见到用户；独立 → 能一个人起步。
- 不写薪资、岗位数量等没核实的数字。

## 三、城市（脚本自动）

脚本从 `references/cities.json` 挑 4 座：3 座和 TA 的做事方式、发动机对应的行业合拍，1 座补上 TA 成长环境里少的那一块。报告里**只列名字**；理由在附录，并注明城市特点是印象、没有联网核实、不是建议搬家。

- 不用自己写城市，也不要改脚本给的名单。
- 用户追问“为什么是这座城”时，再用附录里的理由回答。
- 想调整城市库时改 `references/cities.json`，改完跑一次 `<脚本> simulate`，看有没有城市被推荐得过多或一次都没出现。
